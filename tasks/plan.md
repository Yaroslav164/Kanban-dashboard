# Kanban MVP

Пользователь входит по email/password или через GitHub, создаёт личную доску с колонками и карточками и видит сохранённый порядок после перезагрузки. Laravel Reverb доставляет обновления в другие вкладки и устройства того же владельца.

## Модель PostgreSQL 16

| Таблица | Поля и ограничения | Индекс для активных строк |
|---|---|---|
| users | bigint PK, имя, нормализованный email UNIQUE, хеш пароля NULL, github_id UNIQUE NULL, временные метки | По уникальному email и GitHub ID |
| boards | bigint PK, user_id FK → users.id, title, временные метки | (user_id, id) |
| columns | bigint PK, board_id FK → boards.id, title, position integer, временные метки | (board_id, position, id) |
| cards | bigint PK, column_id FK → columns.id, title, description text NULL, position double precision, временные метки | (column_id, position, id) |

У досок, колонок и карточек обязательны created_at и updated_at, а deleted_at допускает NULL. Частичные индексы используют условие deleted_at IS NULL. Идентификаторы родителей и позиции обязательны. Владельца определяет boards.user_id. Связь пользователей и досок один-ко-многим. FK сохраняют физическую целостность. Новые миграции добавляют объекты, ранее применённые миграции сохраняются.

Удаление доски в одной транзакции отмечает её активные колонки и карточки, удаление колонки — её активные карточки. Поиск каждого ресурса учитывает владельца, активных предков и принадлежность родителю из URL. Все изменения дерева сериализуются короткой блокировкой строки доски. После получения блокировки сервис повторно проверяет состояние затронутых объектов. Транзакции на разных досках независимы.

## Контракт приложения

Оба способа входа создают cookie-сессию Sanctum. GitHub OAuth через Socialite проверяет state и сохраняет стабильный ID GitHub. Для новой учётной записи требуется подтверждённая почта GitHub. Совпадение email с существующей учётной записью требует подтверждения владельца через вход. Секрет GitHub хранится в окружении сервера.

Вошедший пользователь может явно привязать GitHub в настройках учётной записи. SPA обрабатывает успешный callback на /boards, ошибку входа на /login и ошибку привязки на /settings/account.

Reverb доставляет событие board.changed с board_id в приватный канал владельца после успешного commit. Подписка авторизуется через сессию Sanctum. Клиент сначала подписывается, затем загружает актуальный снимок, а при повторной подписке обновляет список и открытую доску. Уведомления за время запроса вызывают повторное чтение. Удаление открытой доски возвращает пользователя к списку. Тесты проверяют отсутствие события при rollback, отказ при подписке на чужой канал и синхронизацию двух вкладок владельца.

Полное описание запросов, ответов и кодов ошибок находится в [OpenAPI 3.0](../docs/openapi.yaml). GET отдельной доски возвращает колонки с упорядоченными карточками для первого отображения. Коллекции и ответы на создание или редактирование ресурса возвращают данные в поле data. Изменение владельца, родителя или позиции напрямую через PATCH исключено из контракта.

Сервер назначает позицию карточки по идентификаторам соседей в целевой колонке. Перемещаемая карточка исключается из списка при проверке соседства. NULL обозначает соответствующий край списка, два NULL — пустую целевую колонку. Для соседей с позициями 1024 и 2048 новая позиция равна 1536. На краю применяется шаг 1024. Если между значениями double больше нет представимого числа, сервер под той же блокировкой перенумеровывает активные карточки целевой колонки и повторяет вставку. Обычная вставка обновляет одну карточку. Устаревшие соседи дают 409, клиент перечитывает доску. Фронтенд применяет ответ успешного перемещения и восстанавливает порядок после сбоя.

Controller валидирует форму запроса и формирует HTTP-ответ. Service применяет правила владения, порядка и удаления, Repository выполняет запросы и блокировки, Model задаёт отношения и soft-delete. Unit of Work открывает одну DB::transaction на команду сервиса. Сервис явно подтверждает успешный результат через commit, rollback прерывает callback исключением. Исключение или выход без явного подтверждения приводят к откату. Физическим commit/rollback управляет Laravel. Проверка через Pest воспроизводит ошибку между двумя записями и проверяет отсутствие частичного изменения.

## Выполнение и приёмка

После согласования запускаются инфраструктура, схема БД и клиент по принятому контракту. Серверные тикеты начинаются после проверки миграций. Владельцы, зависимости и проверки перечислены в [чеклисте](todo.md).

Из корня проекта должны выполняться `php artisan test`, `./vendor/bin/pest --coverage --min=80` с PCOV для app/, `npm run test`, `./vendor/bin/pint --test`, `npm run lint` и `php artisan l5-swagger:generate`. Swagger UI открывается по /api/documentation. CI сравнивает разобранный YAML из аннотаций с утверждённым контрактом, затем сверяет ответы работающего API со схемами. Браузерный smoke-тест выполняет вход, перенос, перезагрузку и проверку порядка.

После согласования стека проект использует Laravel 13.43.0 и PHP 8.3.
